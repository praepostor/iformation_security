# Fundamentals_of_information_security — курс по основам информационной безопасности

**Это курс по основам информационной безопасности.**

Репозиторий содержит последовательный учебный маршрут от базовых ИТ-навыков и понимания сетевого взаимодействия до анализа угроз, сетевого трафика, вредоносной активности, средств защиты, криптографических хэш-функций, безопасной работы с ИИ и правовых аспектов информационной безопасности.

Курс рассчитан на начинающих: сложные понятия вводятся через практические задачи, наблюдаемые технические факты и безопасные учебные сценарии. В материалах последовательно проводится важная профессиональная логика: **факт → интерпретация → гипотеза → проверка → риск → защитная мера → контроль результата**. Практические задания не требуют эксплуатации реальных уязвимостей, запуска вредоносного ПО или вмешательства в чужую инфраструктуру.

Отдельная часть курса посвящена современным сценариям работы с ИИ: пользовательскому взаимодействию через ChatGPT/Qwen и аналогичные интерфейсы, программному сценарию через API и агентному сценарию с инструментами на примере OpenCode.

## Item 3 — вредоносное ПО, диагностика процессов и проектирование ИИ-ассистентов

**Папка:** [`item_3`](./item_3)

Раздел посвящён безопасному анализу признаков вредоносной активности без запуска malware. Основная логика — не искать «вирус по имени», а восстанавливать цепочку наблюдаемых технических признаков: канал появления → запуск → процесс → файл → автозапуск → сеть → изменения → контекст → осторожный вывод. Дополнительно рассматривается создание специализированных ИИ-ассистентов через генератор препромптов.

### Вредоносные программы и защита от них

- [`part_1_malware.md`](./item_3/part_1_malware.md) — практикум по видам вредоносного ПО, каналам проникновения, запуску, закреплению, цифровым следам, сигнатурному/эвристическому/поведенческому обнаружению, антивирусу, EPP/EDR, карантину и первичному реагированию.
- [`part_1_malware_full.md`](./item_3/part_1_malware_full.md) — полная расширенная версия практикума по malware с дополнительной теорией, заполненными примерами, подробным разбором кейсов и многоуровневой защитой.

### Первичная диагностика процессов и признаков вредоносной активности

- [`part_2.md`](./item_3/part_2.md) — полностью консольный практикум для Windows/PowerShell, Linux, WSL и macOS: процессы, PID/PPID, родительские связи, пути и команды запуска, файлы и хэши, автозапуск, сетевые соединения и отделение факта от гипотезы.
- [`part_2_full.md`](./item_3/part_2_full.md) — полная расширенная версия практикума по диагностике процессов с подробными пояснениями, решениями и разборами учебных ситуаций.

## Логика прохождения курса

1. **Item 1:** сформировать базовую ИТ-грамотность — Python, Jupyter Notebook, Git/GitHub, сети и API — и научиться первично классифицировать цифровые инциденты и безопасно анализировать сетевую доступность через Nmap.
2. **Item 2:** перейти к наблюдаемому сетевому уровню — TShark, Wireshark, Ethernet, DNS, TCP и HTTP — и связать технические данные с угрозами информации и свойствами CIA-триады.
3. **Item 2:** изучить ИБ-риски трёх способов взаимодействия с ИИ: пользовательского интерфейса, программного API и агентного сценария.
4. **Item 3:** научиться анализировать признаки вредоносной активности через процессы, файлы, хэши, автозапуск, сеть и временную последовательность событий, не делая вывод по одному индикатору.
5. **Item 3:** освоить проектирование специализированных ИИ-ассистентов через препромпты и мета-промпт/генератор препромптов.
6. **Item 4:** перейти от анализа угроз к проектированию защитного контура: организационные меры, firewall, сегментация, IDS/IPS, VPN, шифрование, хэширование, подпись, сертификаты и PKI.
7. **Item 4:** получить практический опыт контроля целостности через SHA-256/OpenSSL и наблюдения за процессами/сетевыми соединениями с Process Explorer и TCPView.
8. **Item 4:** познакомиться с профессиональным ИБ-ассистентом `Security & Privacy Intelligence Architect` и агентным сценарием разработки через OpenCode и `AGENTS.md`.
9. **Item 5:** завершить курс пониманием правовых границ ИБ: отделять технический факт от профессиональной оценки и окончательной юридической квалификации.

## Три сценария работы с ИИ в рамках курса

### 1. Пользовательский сценарий

Пользователь взаимодействует с ИИ через ChatGPT, Qwen или другой браузерный/настольный интерфейс. Постоянные правила и роль ассистента задаются через системную инструкцию/препромпт. Примеры находятся в `item_2/Prompts_first_AI_use_case` и `item_4/AI/security_privacy_intelligence_architect_preprompt.md`.

С точки зрения ИБ необходимо контролировать, какие данные отправляются внешнему сервису, где они могут храниться, какие инструкции и документы входят в контекст и кто проверяет результат модели.

### 2. Программный сценарий через API

Приложение обращается к модели программно через API. Для понимания этого сценария курс даёт базу по HTTP/HTTPS, API и REST API в `Item_1/part_1_http_https_ftp_ssh.md` и `Item_1/part_2_api_rest_api.md`.

С точки зрения ИБ дополнительно возникают вопросы хранения API-ключей, аутентификации/авторизации, журналирования, rate limits, обработки ошибок, состава передаваемых данных и доверия к машинно полученному ответу.

### 3. Агентный сценарий

ИИ-агент получает доступ к разрешённым инструментам и выполняет последовательность действий: читает код и документы, меняет файлы, запускает команды и тесты. Практический пример находится в `item_4/AI/OpenCode`.

В этом сценарии особенно важны принцип минимальных привилегий, ограничение инструментов, review изменений, тестирование, журналирование действий и правила в `AGENTS.md`. Чем больше автономность агента, тем важнее технические ограничения и человеческие контрольные точки.

## Общая логика курса по информационной безопасности

```text
ИТ-база и устройство систем
→ активы и цифровые события
→ сеть и сетевой трафик
→ угрозы и уязвимости
→ вредоносная активность и цифровые следы
→ процессы и сетевые соединения
→ риск
→ меры и средства защиты
→ контроль целостности и защитный мониторинг
→ безопасная работа с ИИ
→ правовые границы и ответственность
```

Главный методический принцип курса: **не называть событие атакой, вредоносной программой, уязвимостью или правонарушением только по одному признаку**. Сначала фиксируются наблюдаемые факты, затем строится проверяемая гипотеза, после чего выбираются источники подтверждения, защитные меры и контроль результата.
