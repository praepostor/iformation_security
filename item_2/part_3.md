# Анализ Ethernet-кадров, сетевой адресации и доверия в Wireshark

*Практическая работа для начинающих: от установки Wireshark до анализа Ethernet II, DNS, TCP, HTTP и ИБ-рисков сетевого взаимодействия*

| Параметр | Описание |
|---|---|
| **Цель работы** | Научиться захватывать небольшой объём собственного сетевого трафика в Wireshark, находить Ethernet-кадры, читать MAC- и IP-адреса, видеть DNS, TCP и HTTP внутри одного сетевого обмена и объяснять ИБ-риски по наблюдаемым фактам. |
| **Что будет сделано руками** | Выбор сетевого интерфейса → настройка capture filter → захват DNS и HTTP-трафика → анализ Ethernet II → анализ TCP-соединения → анализ HTTP-запроса → просмотр статистики → разбор ИБ-кейсов. |
| **Учебный внешний узел** | `scanme.nmap.org`. В этой работе он используется только как имя обычного DNS/HTTP-обращения. Сканирование портов, подбор паролей, DoS/DDoS и эксплуатация уязвимостей не выполняются. Фактический IP, который вернёт DNS, может отличаться между моментами/сетями; это значение только наблюдается в Wireshark. |
| **Итоговый результат** | Заполненные таблицы, 4 обязательных скриншота, ответы на вопросы, разбор пяти кейсов и итоговый вывод. |
| **Уровень** | Начальный. Все основные термины поясняются по ходу работы. |
| **Рекомендуемое время** | 120–150 минут. |

> **Правило цели этой лабораторной работы:** во всех практических действиях в качестве удалённого веб-узла вводите **только имя `scanme.nmap.org`** или URL `http://scanme.nmap.org/`. Не подставляйте в команды числовой IP-адрес, который покажет DNS. IP-адреса в таблицах ниже нужны только как **наблюдаемые поля из вашего собственного захвата Wireshark**: вы их переписываете из Packet Details, но не используете как отдельную цель. Это позволяет выполнить работу без списка IP-адресов и без отдельного тестового контура.

> **Почему именно `scanme.nmap.org`:** это публичный учебный узел проекта Nmap. В этой работе мы не выполняем сканирование, подбор паролей, нагрузочное тестирование или эксплуатацию. Мы создаём только один обычный DNS-запрос и один обычный HTTP-запрос, чтобы увидеть собственный сетевой обмен в Wireshark.

> **Главное правило безопасности:** захватывайте трафик только на собственном учебном устройстве и только на том интерфейсе, на котором вы имеете право выполнять анализ. Не перехватывайте чужой трафик и не публикуйте файлы захвата в открытом доступе.

> **Почему это важно:** файл `pcap` или `pcapng` может содержать IP- и MAC-адреса, доменные имена, URL, незашифрованные HTTP-заголовки, cookies, служебные идентификаторы и другие сведения. Поэтому файл захвата сам является **информационным активом** — ценным объектом, который нужно хранить и передавать аккуратно.

# 1. Установка Wireshark

## 1.1. Что именно мы устанавливаем

**Wireshark** — графический анализатор сетевых протоколов. Он принимает захваченные кадры и пакеты, разбирает их по протоколам и показывает поля в удобном виде.

Важно отличать два компонента:

- **Wireshark GUI** — графическое окно, в котором мы будем нажимать кнопки, выбирать пакеты и раскрывать поля;
- **механизм захвата** — компонент, который получает пакеты от операционной системы. В Windows для этого обычно используется **Npcap**, а в Linux/macOS доступ к захвату организуется через системные механизмы и `dumpcap`.

> **Для этой работы нужен именно графический Wireshark.** Здесь важно научиться работать с окном программы: выбирать интерфейс, запускать и останавливать захват, применять фильтры, выбирать пакет и раскрывать его поля.

## 1.2. Windows

### Шаг 1. Скачайте установщик

1. Откройте официальный сайт Wireshark.
2. Перейдите в раздел **Download**.
3. Выберите установщик для вашей архитектуры Windows. Для большинства современных ПК это x64.
4. Запустите скачанный `.exe`.

### Шаг 2. Установите Wireshark

1. Нажимайте **Next** по шагам мастера.
2. Оставьте графический компонент Wireshark включённым.
3. Когда мастер предложит установить **Npcap**, не снимайте этот пункт.
4. Завершите установку.

**Npcap** — драйвер захвата пакетов для Windows. Простыми словами, именно он даёт Wireshark возможность получать сетевые пакеты с интерфейсов Windows.

### Шаг 3. Проверка

1. Откройте меню **Пуск**.
2. Найдите **Wireshark**.
3. Запустите программу.
4. На стартовом экране должен появиться список интерфейсов: например, `Wi-Fi`, `Ethernet`, виртуальные адаптеры и другие.
5. Рядом с активным интерфейсом обычно виден небольшой движущийся график трафика.

Если интерфейсы видны, но захват не запускается, сначала проверьте установку Npcap. Не используйте запуск Wireshark от имени администратора как постоянное решение.

## 1.3. Linux: Ubuntu / Debian и производные

Откройте терминал и выполните:

```bash
sudo apt update
sudo apt install wireshark
```

Во время установки система может спросить, разрешать ли обычным пользователям захват пакетов.

Если появляется вопрос вида **«Should non-superusers be able to capture packets?»**, для учебного компьютера выберите **Yes**.

Если вопрос не появлялся или вы выбрали другой вариант, можно повторно открыть настройку:

```bash
sudo dpkg-reconfigure wireshark-common
```

Затем добавьте своего пользователя в группу `wireshark`:

```bash
sudo usermod -aG wireshark "$USER"
```

После этого **выйдите из пользовательской сессии и войдите снова**. Простое закрытие терминала может быть недостаточно, потому что состав групп обычно перечитывается при новом входе.

Запуск:

```bash
wireshark
```

> **Почему не рекомендуется `sudo wireshark`:** графический анализатор обрабатывает сложные входные данные. Безопаснее дать минимально необходимые права специальному компоненту захвата, а само графическое приложение запускать от обычного пользователя.

## 1.6. Windows Subsystem for Linux — WSL

### Сначала главное: WSL — это отдельная Linux-среда

**WSL (Windows Subsystem for Linux)** позволяет запускать Linux внутри Windows без обычной отдельной виртуальной машины, которой пользователь управляет вручную.

Для Wireshark важно понимать, **где создаётся трафик**:

- если браузер, PowerShell или приложение работает в Windows, проще использовать **Wireshark для Windows** и захватывать Windows-интерфейс;
- если команда `curl` выполняется внутри WSL и вы хотите анализировать именно сетевое представление WSL, можно использовать **Wireshark внутри WSL**.

Это не одно и то же. WSL имеет собственное сетевое представление, поэтому список интерфейсов и MAC-адреса могут отличаться от Windows.

### Проверка WSL 2 и GUI

В PowerShell:

```powershell
wsl -l -v
```

Для графических Linux-приложений нужен WSL 2.

Если WSL уже установлен, полезно обновить его:

```powershell
wsl --update
wsl --shutdown
```

После этого снова откройте вашу Linux-дистрибуцию.

### Установка Wireshark внутри Ubuntu в WSL

```bash
sudo apt update
sudo apt install wireshark
```

Если требуется разрешить захват обычным пользователем:

```bash
sudo dpkg-reconfigure wireshark-common
sudo usermod -aG wireshark "$USER"
```

После нового входа в WSL запустите:

```bash
wireshark
```

Если Windows и WSL настроены с поддержкой WSLg, графическое окно появится как обычное приложение Windows.

> **Для новичка:** если задача — просто выполнить эту лабораторную работу на обычном Windows-ноутбуке, используйте нативный Wireshark для Windows. WSL-вариант нужен только если преподаватель специально просит анализировать трафик Linux-среды WSL.

# 2. Wireshark с нуля: что находится перед вами

## 2.1. Что такое сетевой трафик

**Сетевой трафик** — это данные, которыми устройства обмениваются по сети. Когда браузер открывает страницу, система делает DNS-запрос, создаёт TCP-соединение и отправляет HTTP/HTTPS-запросы. На каждом уровне появляются свои заголовки и служебные поля.

Wireshark не «видит смысл всей сети сразу». Он получает последовательность отдельных кадров/пакетов и помогает собрать из них техническую картину.

## 2.2. Что такое захват пакетов

**Packet capture / захват пакетов** — запись сетевых единиц данных, которые проходят через выбранный интерфейс и доступны механизму захвата.

Захват не означает, что Wireshark автоматически видит весь трафик организации. Обычно на обычном ноутбуке виден:

- трафик самого ноутбука;
- широковещательный/многоадресный трафик, доставленный ему;
- отдельные служебные кадры;
- дополнительный трафик только в специально настроенных сетевых сценариях.

## 2.3. Что такое сетевой интерфейс

**Сетевой интерфейс** — программно представленный сетевой адаптер или канал связи.

Примеры:

- Wi-Fi-адаптер;
- Ethernet-карта;
- VPN-интерфейс;
- виртуальный интерфейс WSL/виртуальной машины;
- loopback — внутренний интерфейс для обмена внутри самого компьютера.

> **Почему выбор интерфейса важен:** если вы генерируете трафик через Wi-Fi, а захватываете неактивный Ethernet, нужных кадров в захвате не будет.

## 2.4. Главное окно Wireshark

После захвата основное окно обычно состоит из трёх основных областей.

### 1. Packet List — список пакетов

Это верхняя таблица.

Каждая строка — один захваченный пакет/кадр. Обычно видны столбцы:

- **No.** — порядковый номер;
- **Time** — время относительно начала захвата или другой выбранный формат времени;
- **Source** — источник;
- **Destination** — назначение;
- **Protocol** — протокол, который Wireshark считает наиболее полезным показать для этой строки;
- **Length** — длина;
- **Info** — краткое описание.

### 2. Packet Details — подробности пакета

Это средняя область с деревом протоколов.

Типичная цепочка для обычного HTTP-запроса:

```text
Frame
└── Ethernet II
    └── Internet Protocol Version 4
        └── Transmission Control Protocol
            └── Hypertext Transfer Protocol
```

Стрелка или треугольник слева раскрывает уровень.

### 3. Packet Bytes — байты пакета

Это нижняя область.

Слева показаны байты в шестнадцатеричном виде, справа — их ASCII-представление там, где оно возможно.

Если выбрать поле в **Packet Details**, Wireshark подсветит соответствующие байты в **Packet Bytes**.

> **Зачем это нужно новичку:** средняя панель объясняет смысл поля, а нижняя показывает, что это поле реально занимает определённые байты в захваченном кадре.

## 2.5. Display filter — фильтр отображения

**Display filter** не удаляет пакеты из файла. Он только говорит Wireshark: «покажи мне сейчас строки, которые соответствуют условию».

Примеры:

```text
dns
```

показывает DNS;

```text
tcp.port == 80
```

показывает TCP-пакеты, где один из портов равен 80;

```text
http.request
```

показывает HTTP-запросы.

Поле display filter расположено над **Packet List**. После ввода нажмите **Enter** или кнопку применения фильтра.

## 2.6. Capture filter — фильтр захвата

**Capture filter** применяется **до записи**. Пакеты, не подходящие под условие, вообще не попадут в файл захвата.

В этой работе будет использован:

```text
arp or udp port 53 or tcp port 53 or tcp port 80
```

Разберём по частям:

- `arp` — оставить ARP-кадры;
- `udp port 53` — оставить классический DNS по UDP;
- `tcp port 53` — оставить DNS по TCP, если он встретится;
- `tcp port 80` — оставить TCP-трафик HTTP на порту 80;
- `or` — логическое «ИЛИ»: подходит любое из перечисленных условий.

> **Главное различие:** capture filter уменьшает объём **записываемых** данных, display filter меняет только то, что **показывается на экране** после захвата.

# 3. Сетевая теория

## 3.1. Кадр, пакет, сегмент — это не одно и то же

Новички часто называют всё словом «пакет». Для разговора это допустимо, но в лабораторной полезно различать уровни.

| Термин | Уровень | Простое объяснение |
|---|---|---|
| **Ethernet frame / Ethernet-кадр** | Канальный уровень | То, что передаётся внутри локального Ethernet-сегмента между соседними сетевыми участниками. Содержит MAC-адреса. |
| **IP packet / IP-пакет** | Сетевой уровень | Единица IP. Содержит IP-адрес источника и назначения. Может проходить через несколько маршрутизаторов. |
| **TCP segment / TCP-сегмент** | Транспортный уровень | Часть TCP-обмена. Содержит порты, sequence number, flags и другие поля. |
| **HTTP message** | Прикладной уровень | Запрос или ответ веб-протокола: например `GET /`. |

## 3.2. Инкапсуляция

**Инкапсуляция** — вложение данных одного уровня внутрь структуры другого уровня.

Для нашего HTTP-запроса упрощённая логика такая:

```text
HTTP-запрос
↓ помещается в
TCP-сегмент
↓ помещается в
IP-пакет
↓ помещается в
Ethernet-кадр
```

На принимающей стороне уровни разбираются в обратном порядке.

> **Почему это важно для ИБ:** разные поля отвечают за разные части доверия. MAC помогает локальной доставке, IP определяет сетевое назначение, TCP обеспечивает состояние соединения, HTTP описывает прикладное действие.

## 3.3. Ethernet II

**Ethernet** — семейство технологий локальных сетей. В этой работе нас интересует распространённый формат **Ethernet II**.

Упрощённая структура:

| Поле | Типичный размер | Зачем нужно |
|---|---:|---|
| Преамбула + служебный старт | 8 байт перед основными полями | Синхронизация передачи на физическом уровне. Обычно Wireshark её не показывает как часть обычного захвата. |
| Destination MAC | 6 байт | Кому локально предназначен кадр. |
| Source MAC | 6 байт | От какого локального интерфейса пришёл кадр. |
| EtherType | 2 байта | Какой протокол находится внутри: например IPv4 или ARP. |
| Payload / данные | Переменный размер | Инкапсулированный протокол и его данные. |
| FCS | 4 байта | Контроль ошибок Ethernet. Часто сетевой адаптер проверяет/удаляет FCS до передачи данных Wireshark, поэтому поле может отсутствовать в захвате. |

## 3.4. MAC-адрес

**MAC-адрес** — адрес канального уровня, обычно 48 бит, записанный шестью парами шестнадцатеричных цифр:

```text
3c:52:82:aa:bb:cc
```

MAC используется для локальной доставки Ethernet-кадра.

### Source MAC

MAC отправителя данного локального кадра.

### Destination MAC

MAC следующего локального получателя кадра.

### OUI

**OUI (Organizationally Unique Identifier)** — исторически первые 24 бита глобально назначенного MAC-префикса, связанные с организацией-производителем.

Важно: современные ОС и виртуальные среды могут использовать **locally administered / randomized MAC**, поэтому по первым байтам нельзя всегда надёжно определить производителя физического устройства.

> В старых учебных описаниях оставшуюся часть MAC иногда называют «серийным номером». Для практической работы безопаснее говорить **индивидуальная часть идентификатора интерфейса**: это не обязательно буквальный серийный номер оборудования.

## 3.5. Unicast, broadcast, multicast

**Unicast** — кадр одному конкретному получателю.

**Broadcast** — широковещательный кадр всем участникам локального broadcast domain. Классический Ethernet broadcast MAC:

```text
ff:ff:ff:ff:ff:ff
```

**Multicast** — доставка группе получателей.

## 3.6. IP-адрес

**IP-адрес** — логический адрес сетевого уровня. Он нужен, чтобы сетевой уровень понимал, от какого узла идёт IP-пакет и к какому сетевому назначению его нужно маршрутизировать.

В этой лабораторной работе мы **не вводим числовой IP удалённого узла вручную**. Сначала DNS разрешает имя `scanme.nmap.org`, а затем Wireshark показывает фактический IP уже внутри захваченного пакета. В отчёте обозначайте такие значения, например, как `<IP_вашего_ПК>` и `<IP_scanme_из_захвата>`, а рядом переписывайте фактическое значение только из собственного PCAPNG.

IP нужен для доставки между сетями.

Ключевое отличие:

- MAC действует на текущем локальном участке;
- IP описывает сетевой источник/назначение и обычно сохраняется через маршрутизируемый путь, хотя существуют NAT и другие механизмы, которые могут менять адреса.

## 3.7. Коммутатор и маршрутизатор

**Коммутатор / switch** в простом Ethernet-сценарии пересылает кадры внутри локальной сети, ориентируясь на MAC-адреса.

**Маршрутизатор / router** соединяет разные IP-сети и принимает решение, куда передать IP-пакет дальше.

## 3.8. Шлюз по умолчанию

**Default gateway / шлюз по умолчанию** — маршрутизатор, которому компьютер обычно передаёт IP-пакеты, предназначенные не для своей локальной сети.

Пример логики:

```text
Ваш ПК
   |
   | Ethernet destination MAC = MAC локального next hop
   v
Домашний/офисный маршрутизатор или другой локальный next hop
   |
   | дальше по маршрутизируемой сети
   v
scanme.nmap.org
```

Здесь специально нет числового IP: имя `scanme.nmap.org` разрешит DNS, а фактический адрес вы увидите в своём захвате Wireshark.

Очень важный вывод:

> Когда вы обращаетесь к удалённому серверу, **IP destination** может быть адресом удалённого сервера, а **Ethernet destination MAC** — адресом локального следующего узла, обычно шлюза.

MAC-адрес удалённого веб-сервера через Интернет ваш компьютер обычно не знает и не должен знать: между ними находятся маршрутизаторы, и Ethernet-заголовок меняется на каждом канальном участке.

## 3.9. ARP

**ARP (Address Resolution Protocol)** — протокол IPv4-локальной сети, который помогает узнать, какой MAC-адрес соответствует нужному локальному IPv4-адресу.

Упрощённый смысл ARP-запроса:

```text
«Кто в моём локальном сегменте использует нужный мне локальный IPv4? Сообщите свой MAC».
```

В этой работе не нужно вручную подставлять адрес шлюза. Если ARP попадёт в захват естественным образом, вы прочитаете локальный IPv4 и MAC прямо из полей пакета.

Первоначальный ARP Request часто является broadcast, потому что отправитель ещё не знает MAC владельца IP.

> **ИБ-смысл:** если соответствие IP ↔ MAC неожиданно меняется, это повод для проверки. Но один изменившийся MAC сам по себе ещё не доказывает атаку: устройство могли заменить, сеть могла использовать резервирование, виртуальный шлюз или другую штатную схему.

## 3.10. DNS

**DNS (Domain Name System)** переводит удобное имя сервиса в сетевой адрес.

Пользователь пишет:

```text
scanme.nmap.org
```

а приложение получает IP-адрес, к которому можно строить соединение.

### Что такое DNS resolver

**Resolver / DNS-резолвер** — компонент, которому ваш компьютер задаёт вопрос о доменном имени.

Простыми словами:

```text
Приложение: «Мне нужен scanme.nmap.org»
        ↓
Резолвер: «Я выясню, какой IP соответствует этому имени»
        ↓
Ответ: «Используй такой IP»
```

Резолвером может быть:

- DNS-сервер организации;
- домашний маршрутизатор, пересылающий запросы дальше;
- DNS-сервис провайдера;
- публичный DNS-сервис;
- локальный системный stub-resolver, который затем обращается к настоящему DNS-серверу.

> **ИБ-смысл:** DNS-ответ влияет на направление подключения. Поэтому доверие к имени требует доверия к процессу разрешения имени и, для защищённых веб-сервисов, дополнительной проверки TLS-сертификата.

## 3.11. TCP

**TCP (Transmission Control Protocol)** — транспортный протокол с установлением соединения и контролем последовательности данных.

### Зачем TCP

TCP помогает двум приложениям:

- установить логическое соединение;
- нумеровать передаваемые данные;
- подтверждать получение;
- повторно передавать потерянные данные;
- регулировать поток.

### Трёхстороннее рукопожатие

Перед передачей обычных данных TCP обычно выполняет:

```text
Клиент → Сервер: SYN
Сервер → Клиент: SYN, ACK
Клиент → Сервер: ACK
```

**SYN** — запрос на начало и синхронизацию TCP-соединения.

**ACK** — подтверждение.

## 3.12. Порт

**TCP/UDP port / порт** — число, которое помогает операционной системе понять, какому приложению передать сетевой обмен.

Для обычного HTTP традиционно используется TCP-порт 80.

У клиента при этом обычно появляется **ephemeral port / временный клиентский порт**, например `52144`. Это не «открытый веб-сервис» на ноутбуке, а временный номер конкретного исходящего соединения.

## 3.13. HTTP

**HTTP (Hypertext Transfer Protocol)** — прикладной протокол запрос/ответ.

Пример:

```text
GET / HTTP/1.1
Host: scanme.nmap.org
```

- `GET` — метод запроса ресурса;
- `/` — путь к корневой странице;
- `Host` — имя веб-узла.

**HTTP сам по себе не шифрует содержимое.** Поэтому незашифрованный HTTP удобно анализировать в учебной работе, но нельзя передавать через него реальные секреты, пароли или чувствительные данные.

## 3.14. HTTPS и TLS

**HTTPS** — HTTP внутри защищённого TLS-канала.

**TLS** шифрует прикладные данные и позволяет клиенту проверять сертификат сервера. При обычном HTTPS Wireshark видит сетевые и транспортные поля, но не обязан показывать открытым текстом содержимое HTTP-запроса.

## 3.15. PCAP и PCAPNG

**PCAP** и **PCAPNG** — форматы файлов сетевого захвата.

`pcapng` — современный формат, который Wireshark обычно использует по умолчанию. Он может хранить не только пакеты, но и дополнительную информацию о захвате.

### Почему такой файл — информационный актив

В нём могут быть:

- адреса устройств;
- домены;
- временная линия действий;
- незашифрованные HTTP-поля;
- cookies или токены, если они передавались открыто;
- служебные имена;
- структура взаимодействия систем.

Поэтому файл нельзя бездумно прикладывать к публичной переписке, GitHub issue или открытому облачному диску.

## 3.16. Сетевое доверие и ИБ

При анализе важно не говорить: «адрес правильный — значит всё безопасно».

Сетевое доверие складывается из нескольких признаков:

- имя;
- IP-адрес;
- MAC локального следующего узла;
- маршрут и шлюз;
- сертификат для TLS;
- учётная запись;
- устройство;
- время и контекст события;
- журналы.

Один признак не заменяет остальные.

## 3.17. Доступность и сетевой захват

**Доступность** — возможность выполнить нужное действие в нужный момент и получить результат за приемлемое время.

Wireshark может показать признаки сетевой деградации:

- повторные TCP-передачи;
- сбросы соединения;
- длительные паузы;
- ошибки прикладного протокола;
- необычно большое число служебных кадров.

Но важное правило:

> **Один признак в PCAP не доказывает DoS/DDoS.** Для вывода нужны контекст нагрузки, несколько источников данных, метрики сервиса, журналы, число источников и понимание того, какой ресурс исчерпывается.

## 3.18. Мини-словарь терминов, которые встретятся в кейсах

Ниже термины, которые в реальной работе часто произносят без пояснения. Для начинающего специалиста важно понимать их буквально.

- **DHCP (Dynamic Host Configuration Protocol)** — протокол автоматической выдачи сетевых настроек устройству. Через DHCP клиент может получить IP-адрес, маску сети, шлюз по умолчанию и адрес DNS-сервера. ИБ-риск возникает, если параметры пришли от неправильного или ошибочно настроенного источника.
- **Сегмент сети** — часть сети, внутри которой устройства имеют общий сетевой контекст. В учебных примерах это может быть отдельная офисная подсеть или VLAN.
- **VLAN (Virtual Local Area Network)** — логическое разделение одной физической коммутируемой инфраструктуры на отдельные канальные сегменты. Устройства из разных VLAN обычно не общаются напрямую без маршрутизации.
- **STP (Spanning Tree Protocol)** — механизм, который помогает коммутируемой Ethernet-сети избегать опасных L2-петель. L2-петля — ситуация, когда кадры могут циркулировать по замкнутому пути и создавать лишний broadcast-трафик.
- **MAC table / таблица MAC-адресов коммутатора** — таблица, где коммутатор запоминает, за каким физическим или логическим портом он видел определённый MAC-адрес. Она помогает понять локальное положение устройства.
- **HA (High Availability, высокая доступность)** — архитектура с резервированием, где отказ одного компонента не должен полностью остановить сервис.
- **Failover / аварийное переключение** — переход с основного компонента на резервный. Из-за штатного failover адрес или MAC шлюза иногда может измениться.
- **VRRP (Virtual Router Redundancy Protocol)** — один из протоколов резервирования шлюза. Несколько маршрутизаторов могут представлять один виртуальный шлюз, поэтому при переключении сетевые признаки могут отличаться от простого сценария «один IP — одно физическое устройство».
- **Метрика** — числовой показатель состояния системы. Например, время ответа, число запросов или доля ошибок.
- **RPS (Requests Per Second)** — число запросов в секунду. Большой RPS сам по себе не доказывает атаку: важно, справляется ли сервис и насколько дороги запросы.
- **Latency** — задержка, то есть сколько времени проходит до получения результата или ответа.
- **Error rate** — доля запросов, завершившихся ошибкой.
- **p95 / p99 latency** — показатели «хвоста» задержек: p95 означает, что примерно 95% измерений не превышают это значение, а оставшаяся часть медленнее. Они помогают увидеть проблему, которую может скрыть среднее значение.
- **Узкое место (bottleneck)** — компонент или ограниченный ресурс, который первым перестаёт справляться и тормозит весь пользовательский сценарий.
- **Backend** — серверная часть приложения, которая выполняет бизнес-логику, обращается к базе данных и другим сервисам. Пользователь обычно не видит её напрямую.
- **API (Application Programming Interface)** — программный интерфейс, через который одна программа обращается к другой по формализованным запросам.
- **Rate limiting** — ограничение частоты запросов, чтобы один пользователь, ключ или сценарий не забрал слишком много общего ресурса.
- **Graceful degradation / контролируемая деградация** — заранее продуманный режим, при котором система временно ограничивает второстепенные функции, но сохраняет критичные действия.
- **Sanitization / санитизация данных** — удаление, маскирование или замена чувствительной информации перед передачей файла другому человеку. Для PCAPNG это может означать подготовку безопасной учебной копии вместо публикации исходного захвата.

# 4. Рабочая ситуация

> **Чем эта работа отличается от исходной лабораторной:** здесь нет Mininet, готовых узлов H1/H3, списка IP-адресов и задания `ping` по выданной топологии. Мы используем другой сценарий: собственный короткий захват → DNS для `scanme.nmap.org` → один HTTP-запрос → разбор Ethernet II, TCP и HTTP. Исходная лабораторная используется только как методическая основа для изучения полей Ethernet II и интерфейса Wireshark; задания и кейсы здесь другие.

Вы — начинающий специалист, которому нужно понять, **как один обычный запрос к удалённому веб-узлу выглядит на разных сетевых уровнях**.

Вы должны:

1. захватить ограниченный объём собственного трафика;
2. получить DNS-ответ для `scanme.nmap.org`;
3. создать одно обычное HTTP-соединение;
4. найти Ethernet II;
5. определить Source MAC и Destination MAC;
6. найти IP-адреса;
7. найти TCP-порты и SYN/SYN-ACK/ACK;
8. найти HTTP GET;
9. сравнить канальный и сетевой уровни;
10. сохранить результат и провести первичную ИБ-интерпретацию.

> Практическая цепочка работы: **DNS → TCP → HTTP → Ethernet-анализ → ИБ-интерпретация**. Мы создаём только небольшой объём обычного клиентского трафика и затем пассивно изучаем его в Wireshark.

# 5. Подготовка к захвату: интерфейс Wireshark шаг за шагом

## 5.1. Откройте Wireshark

После запуска вы увидите **Welcome Screen**.

Слева или в центральной части будет раздел **Capture** со списком сетевых интерфейсов.

### Как понять, какой интерфейс нужен

Если вы подключены по Wi-Fi:

1. найдите строку `Wi-Fi`, `wlan0`, `wlp...` или аналогичную;
2. посмотрите на маленький график активности;
3. откройте в браузере любую разрешённую страницу;
4. убедитесь, что график на этом интерфейсе заметно меняется.

Если подключение по кабелю — ищите `Ethernet`, `eth0`, `enp...`, `eno...`.

В macOS имена могут выглядеть как `en0`, `en1`.

В WSL — обычно будет виртуальный интерфейс Linux, часто `eth0`.

> **Очень важная проверка именно для этой работы:** после короткого пробного захвата выберите любой обычный IP-пакет и посмотрите среднюю панель **Packet Details**. Там должна присутствовать строка **Ethernet II**, если выбранный интерфейс даёт Ethernet-представление кадров. На некоторых Wi-Fi, VPN, loopback или виртуальных интерфейсах Wireshark может показывать другой тип канального заголовка, например IEEE 802.11 или специальный pseudo-header. Это не ошибка Wireshark, но такой интерфейс хуже подходит для задания, где нужно именно сравнивать поля Ethernet II. Если `Ethernet II` не появляется ни в одном подходящем пакете, зафиксируйте это и уточните у преподавателя, какой интерфейс использовать.

## 5.2. Откройте Capture Options

1. Один раз щёлкните нужный интерфейс.
2. В верхнем меню выберите **Capture → Options…**.
3. Откроется окно **Capture Options**.
4. Оставайтесь на вкладке **Input**.

В таблице интерфейсов найдите выбранную строку.

## 5.3. Установите capture filter

В столбце **Capture Filter** дважды щёлкните ячейку выбранного интерфейса и введите:

```text
arp or udp port 53 or tcp port 53 or tcp port 80
```

Если в вашей версии окно выглядит немного иначе, найдите поле **Capture filter for selected interfaces** и введите тот же фильтр.

### Что мы сознательно НЕ записываем

Такой фильтр не должен записывать весь трафик ноутбука. Это уменьшает вероятность случайно собрать лишние данные других приложений.

### Что мы сознательно записываем

- ARP — если он появится естественным образом;
- классический DNS;
- TCP на порту 80 для учебного HTTP-запроса.

## 5.4. Начните захват

Нажмите **Start** в нижней части окна Capture Options.

Альтернативный путь в других версиях:

- выбрать интерфейс на стартовом экране;
- использовать **Capture → Start**.

После запуска строки начнут появляться в **Packet List**.

# 6. Создание учебного трафика

## 6.1. Сначала DNS

Откройте терминал/PowerShell **в той же операционной среде, трафик которой вы захватываете**.

Выполните:

```text
nslookup scanme.nmap.org
```

### Что делает `nslookup`

`nslookup` явно просит настроенный DNS-резолвер разрешить имя `scanme.nmap.org` в IP-адрес.

Это удобно для лабораторной работы, потому что мы создаём понятное событие DNS, которое затем ищем в Wireshark.

### Если команда `nslookup` не найдена

`nslookup` — отдельная диагностическая утилита DNS. На Windows и macOS она обычно уже доступна. В минимальной Linux-системе пакет может отсутствовать. Тогда установите его:

Ubuntu / Debian:

```bash
sudo apt install dnsutils
```

Arch Linux / Manjaro:

```bash
sudo pacman -S bind
```

Fedora:

```bash
sudo dnf install bind-utils
```

После установки снова выполните `nslookup scanme.nmap.org`.

> **Не копируйте найденный IP в следующую команду.** Результат `nslookup` нужен только для понимания работы DNS и последующего сравнения с Wireshark. HTTP-запрос ниже снова выполняется **по имени `scanme.nmap.org`**. Так мы видим естественную цепочку «имя → DNS → IP внутри пакета», а не работаем со списком числовых адресов.

## 6.2. Затем обычный HTTP-запрос

### Windows PowerShell / CMD

```powershell
curl.exe http://scanme.nmap.org/
```

### Linux / WSL / macOS

```bash
curl http://scanme.nmap.org/
```

### Что делает `curl`

`curl` — клиент для сетевых протоколов. Здесь он выполняет один обычный HTTP-запрос к веб-странице.

Если Linux сообщает `curl: command not found`, установите пакет `curl` обычным менеджером пакетов:

- Ubuntu / Debian: `sudo apt install curl`;
- Arch Linux / Manjaro: `sudo pacman -S curl`;
- Fedora: `sudo dnf install curl`.

Почему указан `http://`, а не `https://`:

- HTTP на порту 80 позволяет увидеть прикладной запрос в Wireshark открытым текстом;
- это только учебный запрос публичной страницы;
- не вводите в этот HTTP-сеанс пароли, токены, cookies или любые чувствительные данные.

Если `scanme.nmap.org` временно недоступен, не пытайтесь многократно повторять запрос и не подставляйте случайный IP или другой внешний сайт. Зафиксируйте техническую проблему и сообщите преподавателю. В рамках этой версии работы удалённой целью остаётся только `scanme.nmap.org`.

## 6.3. Остановите захват

## Кейс 1. У шлюза неожиданно изменился MAC-адрес

### Термины перед кейсом

**Шлюз по умолчанию** — локальный маршрутизатор, которому рабочая станция передаёт трафик в другие сети.

**ARP** — механизм сопоставления IPv4-адреса локального узла и его MAC-адреса.

**Baseline / базовая линия** — зафиксированное нормальное состояние, с которым сравнивают текущее.

**DHCP** — протокол автоматической выдачи сетевых параметров. В расследовании он полезен, потому что помогает понять, какие IP, шлюз и DNS получил клиент.

**Сертификат** — цифровой объект, который в HTTPS/TLS помогает клиенту проверить заявленное имя сервера и цепочку доверия.

### Ситуация

В учебной документации для рабочей станции зафиксирован **ожидаемый MAC-адрес локального шлюза**. Числовой IPv4 в кейсе намеренно не приводится: студент работает не со списком адресов, а с наблюдаемыми полями собственного захвата.

Утром аналитик открыл короткий PCAPNG, созданный во время обычного обращения к `scanme.nmap.org`, и заметил: у исходящих Ethernet II кадров Destination MAC отличается от ранее зафиксированного baseline. При этом настройка шлюза в ОС выглядит неизменной.

В журнале изменений нет записи о замене сетевого оборудования. Сеть продолжает работать. Неизвестно, связано ли изменение MAC с резервированием, виртуализацией, штатным изменением сети, ошибкой или нежелательным вмешательством.

## Кейс 2. Одно имя — разные DNS-ответы

### Термины перед кейсом

**DNS** — система сопоставления имени сервиса с IP-адресом.

**DNS resolver** — компонент, которому клиент отправляет DNS-запрос.

**DNS-spoofing** — защитный термин для ситуации, где клиент получает недостоверное соответствие имени и адреса. Сам по себе неожиданный DNS-ответ ещё не доказывает злонамеренную подмену.

**TLS-сертификат** — цифровой сертификат, который помогает клиенту проверить заявленную подлинность HTTPS-сервера.

### Ситуация

Два студента в разное время выполняют одинаковый учебный запрос имени `scanme.nmap.org`. В двух сохранённых PCAPNG DNS-ответы содержат разные числовые адреса. Числовые значения в кейсе намеренно не приводятся: они рассматриваются только как наблюдаемые результаты DNS.

Преподаватель просит определить, означает ли различие автоматическую подмену DNS. Дополнительно известно, что один из студентов при отдельном обращении по HTTPS увидел предупреждение о сертификате, а другой — нет. Документации о причине различия адресов пока нет. Этот кейс **аналитический**: не нужно создавать дополнительную нагрузку или пытаться воспроизводить подозрительное поведение.

## Кейс 3. В сегменте резко вырос broadcast ARP

### Термины перед кейсом

**Broadcast** — локальная передача кадра всем участникам broadcast domain.

**ARP Request** часто передаётся broadcast, когда отправитель ищет MAC по локальному IPv4.

**Деградация** — сервис ещё работает, но хуже нормы: растут задержки, ошибки или нестабильность.

**DoS** — нарушение доступности за счёт исчерпания ресурса. Термин нельзя назначать только по одному большому числу пакетов.

**CPU (Central Processing Unit)** — процессор. Его загрузка показывает только один ресурс сервера; нормальный CPU не означает, что сеть, очередь, база данных и другие компоненты тоже в норме.

**Broadcast domain** — область локальной сети, в пределах которой широковещательный Ethernet-кадр доставляется множеству участников.

### Ситуация

В одном учебном сегменте сотрудники жалуются на медленное открытие внутренних ресурсов.

Короткий PCAP показывает, что значительная часть кадров — ARP Request с Destination MAC `ff:ff:ff:ff:ff:ff`. Многие запросы повторяются. В другом сегменте такой картины нет. Сервер приложений по внутреннему мониторингу не показывает высокой загрузки CPU.

## Кейс 4. PCAPNG приложили к публичной задаче

### Термины перед кейсом

**PCAP/PCAPNG** — файл сетевого захвата.

**HTTP header / HTTP-заголовок** — служебное поле HTTP-запроса или ответа. Некоторые заголовки могут содержать cookies, токены авторизации и другие чувствительные данные.

**Cookie** — небольшое значение, которое веб-клиент хранит и отправляет серверу; часть cookies может использоваться для сессии.

**Bearer token** — секретный токен, предъявление которого может давать доступ от имени владельца токена.

**Capture filter / фильтр захвата** — правило, которое ограничивает данные ещё **до записи в PCAPNG**. Например, фильтр может разрешить записывать только DNS и TCP/80. Если фильтра нет, Wireshark может сохранить намного больше фонового трафика рабочего компьютера.

**Репозиторий** — хранилище файлов и истории изменений проекта, часто управляемое Git. Публичный репозиторий доступен широкому кругу пользователей, поэтому чувствительный PCAPNG туда помещать нельзя.

**Сессия** — логический период работы пользователя с сервисом после входа. Сессионная cookie может быть частью механизма, который связывает последующие HTTP-запросы с уже аутентифицированным пользователем.

## Кейс 5. Главная страница работает, отчёт возвращает 503

### Термины перед кейсом

**HTTP 503 Service Unavailable** — ответ приложения/веб-инфраструктуры, означающий, что сервис в данный момент не может нормально обработать запрос.

**Partial outage / частичный отказ** — часть функций работает, но важный пользовательский сценарий не выполняется.

**TCP retransmission** — повторная TCP-передача данных.

**Latency** — задержка/время ожидания ответа.

**Error rate** — доля запросов, завершившихся ошибками.

**Метрика** — числовой показатель состояния системы, который измеряется во времени. Для доступности полезны RPS, latency, error rate, загрузка ресурсов и состояние очередей.

**Узкое место** — ресурс или компонент, который первым достигает своего предела и начинает тормозить весь сценарий.

**Graceful degradation / контролируемая деградация** — режим, при котором второстепенную тяжёлую функцию можно временно ограничить, чтобы сохранить критичные операции сервиса.

### Ситуация

Пользователь открывает главную страницу внутренней аналитической системы без заметной задержки. Но при запуске большого отчёта через несколько секунд получает HTTP 503.

Wireshark в коротком захвате показывает стабильное TCP-соединение к веб-сервису и HTTP-ответ 503. Фильтр retransmission почти ничего не показывает. В логах поддержки есть жалобы только на отчёты; вход и просмотр коротких карточек работают.
