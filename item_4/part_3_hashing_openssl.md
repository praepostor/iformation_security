# Практическая работа: создание и проверка SHA-256-хэшей с помощью OpenSSL



> **Главная идея:** хэш помогает проверить, совпадает ли текущее состояние файла с ранее зафиксированным эталоном. Хэш **не шифрует** файл, **не скрывает** его содержимое и сам по себе **не доказывает**, кто создал файл. В этой работе основной алгоритм — **SHA-256**.

---

# 1. Цель работы

Научиться:

- устанавливать и запускать OpenSSL в Windows, WSL, Linux и macOS;
- создавать SHA-256-хэш текстового файла;
- понимать формат результата OpenSSL;
- видеть, что изменение файла приводит к другому хэшу;
- сохранять контрольный хэш как эталон;
- повторно вычислять хэш и сравнивать его с эталоном;
- отличать **целостность** от **подлинности** и **конфиденциальности**;
- понимать, почему доверие к эталонному хэшу так же важно, как сам алгоритм;
- оформлять вывод без необоснованных утверждений.

# 3. Короткая теория

## 3.1. Что такое хэш-функция

**Хэш-функция** — математический алгоритм, который получает данные произвольного размера и создаёт значение фиксированной длины.

Например:

```text
файл → SHA-256 → хэш
```

Для SHA-256 результат содержит 256 бит. В привычном шестнадцатеричном виде это 64 символа.

Пример формы результата:

```text
212e217506f48a920fc4608b3ae7d4e3b1a68142326fe90e70641374e8259b72
```

Этот пример показывает **формат**, а не значение, которое нужно копировать в отчёт.

## 3.2. Что такое хэш, digest и контрольная сумма

В этой работе используются близкие по смыслу слова:

- **хэш** — результат работы хэш-функции;
- **message digest / digest** — «цифровой отпечаток» данных; OpenSSL использует термин `dgst`;
- **контрольный хэш** — хэш, сохранённый для последующего сравнения;
- **эталонный хэш** — контрольное значение, которому мы доверяем при проверке.

Слово **checksum / контрольная сумма** часто используется шире. В учебном отчёте лучше писать точно: **SHA-256-хэш файла**.

## 3.3. Почему одинаковый файл даёт одинаковый хэш

Хэш-функция детерминирована: одинаковые байты на входе дают одинаковый результат.

```text
Файл A → SHA-256 → H1
тот же Файл A → SHA-256 → H1
```

Если байты изменились:

```text
Файл A* → SHA-256 → H2
```

и `H2` должен отличаться от `H1`.

## 3.4. Почему даже маленькое изменение важно

Хэш считается **по байтам**, а не «по смыслу текста».

Измениться может:

- буква;
- цифра;
- пробел;
- перевод строки;
- кодировка;
- скрытый служебный байт.

Поэтому два документа, которые визуально кажутся одинаковыми, иногда имеют разные хэши.

## 3.5. Что такое avalanche effect

**Avalanche effect / лавинный эффект** — полезное свойство криптографической хэш-функции: небольшое изменение входных данных приводит к сильно отличающемуся результату.

Это не означает, что «изменился один символ хэша». Обычно изменяется большая часть отображаемого значения.

## 3.6. Хэш не является шифрованием

**Шифрование** предназначено для сокрытия содержания так, чтобы уполномоченная сторона могла восстановить исходные данные с помощью ключа.

**Хэширование** предназначено для получения контрольного значения. Нормальной операции «расшифровать SHA-256 обратно в файл» нет.

Упрощённо:

| Механизм | Главная задача | Можно штатно получить исходный файл обратно? |
|---|---|---|
| Шифрование | Конфиденциальность | Да, с правильным ключом |
| Хэширование | Контроль состояния/целостности | Нет |

## 3.7. Хэш и целостность

**Целостность** — свойство информации, связанное с сохранением правильного и ожидаемого состояния данных.

Упрощённая проверка:

```text
1. Вычислили SHA-256 исходного файла.
2. Сохранили хэш как эталон.
3. Позже снова вычислили SHA-256.
4. Сравнили значения.
```

Если значения различаются, байты файлов различаются.

## 3.8. Очень важное ограничение: совпадение хэшей не равно доказанной подлинности

Представьте, что злоумышленник смог заменить:

- сам файл;
- и текстовый файл рядом с ним, где записан «правильный» SHA-256.

Тогда проверка может показать совпадение, хотя оба объекта были заменены.

Поэтому есть два разных вопроса:

1. **Совпадает ли файл с контрольным значением?**
2. **Можно ли доверять самому контрольному значению?**

Для второго вопроса могут применяться цифровая подпись, доверенный HTTPS-источник, отдельный защищённый канал, PKI и организационные процедуры.

## 3.9. Что такое цифровая подпись

**Цифровая подпись** — криптографический механизм, который связывает данные с операцией, выполненной соответствующим закрытым ключом.

В этой работе мы подпись не создаём. Она нужна для понимания ограничения обычного хэша: подпись может дать дополнительную проверяемую связь с ключом, тогда как один SHA-256 такого свойства не создаёт.

## 3.10. Что такое коллизия

**Коллизия** — ситуация, когда два разных входных сообщения имеют одинаковый хэш.

Поэтому формулировка «хэш всегда абсолютно уникален» технически неверна.

Для современных криптографических алгоритмов задача состоит в том, чтобы практический поиск коллизий был чрезвычайно трудным. SHA-256 применяется именно как современный базовый вариант для подобных учебных проверок.

## 3.11. Почему в работе не используется MD5 как основной алгоритм

MD5 исторически встречается в старых системах и иногда используется для незащитных технических задач, но его нельзя выбирать как современный механизм защиты от намеренной подмены.

## 3.12. Почему SHA-1 тоже не выбирается как основной алгоритм

SHA-1 устарел для новых задач криптографической защиты. Современная практика должна использовать более сильные семейства, например SHA-2 или SHA-3. В этой лабораторной выбран SHA-256 из семейства SHA-2.

# 4. Что такое OpenSSL

**OpenSSL** — набор криптографических библиотек и консольных инструментов.

В этой работе нужен его командный интерфейс:

```text
openssl
```

Команда для хэширования будет выглядеть так:

```bash
openssl dgst -sha256 имя_файла
```

Разберём её:

- `openssl` — запускаем программу OpenSSL;
- `dgst` — работаем с message digest, то есть хэшем;
- `-sha256` — явно выбираем SHA-256;
- `имя_файла` — данные, для которых вычисляется хэш.

> OpenSSL умеет намного больше: работать с TLS, сертификатами, ключами, подписями. В этой лабораторной мы используем только безопасную операцию вычисления хэша.

Откройте терминал.

Обновите информацию о пакетах:

```bash
sudo apt update
```

Установите OpenSSL и `curl`:

```bash
sudo apt install openssl curl
```

- `sudo` — выполнить административную операцию с повышенными правами;

```bash
openssl version
```

```bash
openssl list -digest-algorithms | grep -i sha256
```

Если в выводе встречается SHA-256, можно продолжать.

# 12. Этап 6. Создайте новый файл для проверки целостности

Для проверки целостности создадим новый объект — текстовый файл конфигурации учебного сервиса.

# 13. Этап 7. Сохраните эталонный SHA-256

## Linux / WSL

```bash
openssl dgst -sha256 -r service_config.txt | awk '{print $1}' > service_config.sha256.ref
cat service_config.sha256.ref
```

## macOS

```bash
"$OPENSSL" dgst -sha256 -r service_config.txt | awk '{print $1}' > service_config.sha256.ref
cat service_config.sha256.ref
```

## Windows PowerShell

```powershell
$CurrentHash = ((openssl dgst -sha256 -r service_config.txt) -split '\s+')[0]
$CurrentHash | Set-Content service_config.sha256.ref
Get-Content service_config.sha256.ref
```

### Что такое `-r`

Ключ `-r` меняет формат вывода OpenSSL так, чтобы хэш находился в начале строки. Это удобно для извлечения значения.

### Что делает `awk '{print $1}'`

На Linux/macOS `awk` берёт первое поле строки — сам хэш — и не сохраняет имя файла.

### Что делает PowerShell `-split '\s+'`

Он разбивает строку по пробельным символам. `[0]` означает: взять первый элемент, то есть сам хэш.

# 14. Этап 8. Проверьте неизменённый файл

Сначала **ничего не меняйте** в `service_config.txt`.

## Linux / WSL

```bash
openssl dgst -sha256 -r service_config.txt | awk '{print $1}' > service_config.sha256.current

```

## macOS

```bash
"$OPENSSL" dgst -sha256 -r service_config.txt | awk '{print $1}' > service_config.sha256.current
cmp -s service_config.sha256.ref service_config.sha256.current && echo "OK: HASH MATCH" || echo "ALERT: HASH MISMATCH"
```

## Windows PowerShell

```powershell
$CurrentHash = ((openssl dgst -sha256 -r service_config.txt) -split '\s+')[0]
$CurrentHash | Set-Content service_config.sha256.current

if ((Get-Content service_config.sha256.ref).Trim() -eq (Get-Content service_config.sha256.current).Trim()) {

} else {

}
```

**Current / текущее значение** — хэш, вычисленный во время проверки.

**Match / совпадение** — значения одинаковы.

**Mismatch / несовпадение** — значения различаются.

# 22. Типовые ошибки новичка

## Ошибка 1. «Хэш — это зашифрованный файл»

Нет. Хэш — контрольное значение, а не обратимо зашифрованная копия.

## Ошибка 2. «У двух разных файлов хэш всегда гарантированно разный»

Нельзя давать абсолютную математическую гарантию: существуют коллизии. Практическая безопасность зависит от стойкости выбранной функции.

## Ошибка 3. «Совпало — значит файл точно от правильного автора»

Нет. Нужно отдельно доверять эталонному значению и источнику.

## Ошибка 4. «Не совпало — значит нас взломали»

Нет. Причиной могут быть нормальная новая версия, повреждение, другая кодировка, ошибка копирования или иное изменение.

## Ошибка 5. Копировать хэш из методички

Хэш должен быть вычислен для **вашего фактического файла**.

## Ошибка 6. Сравнивать всю строку OpenSSL и Get-FileHash

Сравнивайте само шестнадцатеричное значение. Формат оболочки может отличаться.

## Ошибка 7. Использовать MD5/SHA-1 по привычке в новой защитной задаче

Наличие команды не означает, что алгоритм подходит для новой криптографической защиты.
